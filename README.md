## 👋 はじめまして、rx-tomo です

社内向けの業務システムや BtoB SaaS を中心に、設計・実装・運用まで一貫して取り組んでいます。
最近は「機能を作る」だけでなく、**安心して使い続けられるプロダクトに育てる**こと（品質・計測・運用・公開品質）に比重を置いています。

企業におけるIT担当者として事業基盤の設計・運用に携わりながら、
AIや自律的な開発環境に関する検証・研究も継続しています。

ここで公開している内容は、個人としての技術探索や設計思考の記録であり、
所属組織の公式見解を示すものではありません。
業務領域と重複しない範囲で、技術の可能性を広く検証しています。

> ⚠️ 実際のコードは機密性の高い社内プロジェクトが多いため公開できませんが、取り組みの進め方・改善の考え方・再利用できる型は非機密ベースで発信していきたいと考えています。

---

### 🧠 関心のあるテーマ・取り組み

- **BtoB / エンタープライズ向けプロダクト開発**
  権限や組織構造など「現場で必要になる複雑さ」を前提に、破綻しない設計と実装を意識しています。
- **品質を落とさないための仕組みづくり**
  重要なユーザー導線を自動テストでカバーし、変更しても壊れにくい状態を保つことに興味があります。
- **計測と改善のループ**
  使われ方を正しく捉えるための計測を整え、改善に繋がる形で実装とドキュメントを揃えます。
- **公開品質（SEO / OGPなど）の改善**
  記事やページが共有されたときに“伝わる”状態を作るため、表示・メタ情報・生成画像などを丁寧に整備します。
- **運用を見据えた基盤整備（DB/アップデート対応）**
  アップデートや移行時に詰まりやすい部分（移行手順、警告対応、衝突回避など）を潰し、運用負荷を下げます。
- **ドキュメント駆動の開発**
  引き継ぎ・進捗・手順書を更新し続け、属人化しない形で進めるのが好きです。

### 📝 直近の活動（2025年12月〜2026年1月）

この期間は、実装そのものよりも
「壊れにくく、改善し続けられる構造」を整えることに注力しました。

#### 1. 改善が回る基盤づくり

- **共有・公開品質の再設計（SEO / OGP / SNS ）**
  AIを活用して共有時の見え方や導線を分析し、実装→検証→修正の反復を半自動化。
  表示品質を偶然ではなく構造で担保できる状態に整理。

- **計測の強化（GAまわり）**
  施策単位で効果を追える設計へ見直し。
  実装と同時にドキュメントも更新し、再現可能な改善ループを整備。

#### 2. 運用リスクの低減

- **データベース運用の整理（アップグレード/移行対応）**
  警告や衝突が発生しやすい箇所を洗い出し、
  手順・前提・注意点をドキュメント化。
  属人化しない移行設計へ改善。

- **E2Eテストの拡充と安定化**
  招待・権限・管理者操作などの重要導線に集中し、
  落ちやすい箇所を継続的に安定化。

#### 3. 設計の抽象化・再利用化

- **データアクセス層の統一**
  実装が増えても破綻しない構造へ整理。
  型と責務を揃え、今後の拡張コストを抑制。

- **ロジック/設計意図の明文化**
  「なぜその実装にしたのか」を追える形で整理。
  引き継ぎ・レビュー・改善をしやすい状態に更新。

#### 4. 技術探索と検証

- AIを活用した開発プロセス改善の検証
- 実装支援・品質確認・設計整理への適用可能性の確認
- 業務と重複しない範囲での自律的開発環境の研究

短期的な成果よりも、
「継続的に改善できる構造」を優先した期間でした。
