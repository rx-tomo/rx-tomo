 ## 👋 はじめまして、rx-tomo です

  社内向けの業務システムや BtoB SaaS を中心に、設計・実装・運用まで一貫して取り組んでいます。
  最近は「機能を作る」だけでなく、**安心して使い続けられるプロダクトに育てる**こと（品質・計測・運用・公開品質）に比重を置いています。

  > ⚠️ 実際のコードは機密性の高い社内プロジェクトが多いため公開できませんが、取り組みの進め方・改善の考え方・再利用できる型は非機密ベースで発信していきたいと考えています。

  ---

  ### 🧠 関心のあるテーマ・取り組み

  - **BtoB / エンタープライズ向けプロダクト開発**
    権限や組織構造など「現場で必要になる複雑さ」を前提に、破綻しない設計と実装を意識しています。
  - **品質を落とさないための仕組みづくり**
    重要なユーザー導線を自動テストでカバーし、変更しても壊れにくい状態を保つのが得意です。
  - **計測と改善のループ**
    使われ方を正しく捉えるための計測を整え、改善に繋がる形で実装とドキュメントを揃えます。
  - **公開品質（SEO / OGPなど）の改善**
    記事やページが共有されたときに“伝わる”状態を作るため、表示・メタ情報・生成画像などを丁寧に整備します。
  - **運用を見据えた基盤整備（DB/アップデート対応）**
    アップデートや移行時に詰まりやすい部分（移行手順、警告対応、衝突回避など）を潰し、運用負荷を下げます。
  - **ドキュメント駆動の開発**
    引き継ぎ・進捗・手順書を更新し続け、属人化しない形で進めるのが好きです。

  ---

  ### 📝 直近の活動（2025年12月〜2026年1月）

  この1ヶ月は、複数プロジェクトで「継続改善」を集中的に進めました。

  - **共有・公開まわりの品質改善**（SEO / OGP / Twitter Card）
    共有時の見え方や導線を改善し、実装→検証→修正を反復
  - **計測の強化**（GAまわり）
    施策の効果が追える状態を作り、実装とドキュメントをセットで整備
  - **データベース運用の改善**（アップグレード/移行対応）
    警告や衝突が起きやすい部分を整理し、手順として残せる形に整備
  - **E2Eテストの拡充と安定化**
    招待・権限・管理者操作などの重要導線で、落ちやすい箇所を継続的に改善
  - **設計の整理（データアクセス層の統一）**
    実装が増えても破綻しにくいように、構造と型を揃える改善を実施
  - **UI刷新・ページ追加 + 引き継ぎ整備**
    画面の再設計・実装と、証跡/引き継ぎの更新を並行で進行
  - **ロジック/設計意図のドキュメント化**
    「あとから追える」形で説明を整備し、共有しやすい状態に更新
