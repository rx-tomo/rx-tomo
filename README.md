# 👋 はじめまして、rx-tomo です

企業の IT / システム担当として、社内向け業務システムや BtoB 領域のプロダクト改善に取り組んでいます。  
設計、実装、運用、計測、ドキュメント整備までをつなげながら、現場で長く使われる仕組みを作ることに関心があります。

最近は Claude Code や Codex などのコーディングエージェントを、単なる実装補助ではなく、企画の立案、市場調査、設計整理、テスト、レビュー、運用記録まで含めた開発プロセス全体の改善にどう組み込むかを継続的に検証しています。

ここで公開している内容は、個人としての技術探索やビジネス設計思考の記録です。所属組織の公式見解ではなく、業務上の機密情報や社内コードは含みません。公開できる範囲で、再利用できる考え方、手順、検証の型を整理していきます。

## 🧭 大切にしていること

- **🛠️ 壊れにくい業務システムを作ること**  
  権限、組織構造、例外処理、運用手順など、実務で後から効いてくる複雑さを前提に設計します。

- **✅ 変更しても安心できる品質基盤を作ること**  
  重要なユーザー導線をテストや確認手順で守り、修正後に何が確認済みかを残すことを重視しています。

- **📈 計測から改善へつなげること**  
  GA / GTM などの計測、ログ、検証結果を、次の改善判断に使える形へ整理します。

- **📚 運用と引き継ぎを前提にすること**  
  実装だけで終わらせず、README、runbook、handoff、Issue、PR の記録を更新し、あとから追える状態を作ります。

- **🤖 AI を使った開発の再現性を高めること**  
  Claude Code / Codex の利用ログやトークン利用の振り返りを通じて、単に多く使うのではなく、停止時間を減らし、検証済みの成果へ変換する使い方を模索しています。

## 🧠 最近の関心領域

### 🤖 AI コーディングエージェントの実務活用

Claude Code や Codex を使い、次のような開発サイクルを検証しています。

- 仕様や既存コードの調査
- 実装方針の整理
- 小さな修正の実装
- lint / typecheck / test / build による検証
- ブラウザでの UI 確認
- PR / Issue / handoff への記録
- 次回以降に再利用できる手順化

特に、25年からの１年近い利用ログを振り返りながら、トークン消費量そのものよりも「どれだけ手戻りを減らせたか」「どれだけ検証と記録に接続できたか」を見るようにしています。

### 🏢 BtoB / エンタープライズ向けの設計

業務システムでは、きれいな画面や単発の機能だけでなく、権限、監査、例外、移行、運用変更に耐える設計が重要だと考えています。  
UI、データ、権限、ドキュメントを分けずに、利用者と運用者の両方が困らない形を目指しています。

### 🔍 品質・計測・公開品質

E2E テスト、手動確認、SEO / OGP、共有時の見え方、分析イベントなど、プロダクトが使われ続けるための周辺品質にも関心があります。  
「作った」だけでなく、「確認できる」「改善できる」「伝わる」状態にすることを大切にしています。
